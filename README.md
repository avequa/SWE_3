# Task 3

Рекомендации товаров на данных маркетплейса Мегамаркет

1. `GET /recommendations/{user_id}` - Вам может понравиться
2. `GET /popular` - «Популярное»
3. `GET /users/{user_id}/recently-viewed` - вы недавно смотрели
4. `GET /items/{item_id}/bought-together` - «С этим товаром покупают»
5. `POST /events/click` - клик по рекомендации

## Данные

[MegaMarket](https://www.kaggle.com/datasets/alexxl/megamarket) — открытые данные маркетплейса
Опубликованны Sber AI Lab вместе со статьёй *From Variability to Stability:
Advancing RecSys Benchmarking Practices* - 196 млн действий 2,7 млн покупателей за 4 месяца

| Колонка | Что это |
|---|---|
| `user_id` | номер покупателя (обезличен) |
| `datetime` | время действия |
| `event` | действие: 0 - заказ, 1 - избранное, 2 - просмотр, 3 - корзина |
| `item_id` | номер товара (обезличен) |
| `category_id` | категория товара |
| `price` | цена (изменена для обезличивания) |

Из датасета берётся выборка: каждый 64-ый покупатель (`EVERY` в `prepare_data.py`)

## Структура

```
.

├── monitoring/           настройки Prometheus и дашборд Grafana
├── Dockerfile
├── docker-compose.yml    api :8001, Prometheus :9091, Grafana :3001

```

## Запуск

Окружение - то же, что для заданий 1 и 2, или отдельное:

```bash
python3.12 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

**1. Датасет** kaggle.com [MegaMarket](https://www.kaggle.com/datasets/alexxl/megamarket) и распаковать в `data`

**2. Подготовить выборку**:

```bash
python prepare_data.py
```

**3. Сравнить методы:**

```bash
python evaluate.py
```

**4. Запустить сервис с мониторингом:**

```bash
docker compose up --build -d
python simulate.py # имитация покупателей
```

| Адрес | Внутри |
|---|---|
| http://localhost:8001/docs | Swagger: документация API и запросы из браузера |
| http://localhost:9091/targets | Prometheus |
| http://localhost:3001/d/recsys | Grafana |


## Как оцениваются рекомендации

`evaluate.py` - история делится по времени: методы видят всё до последних 4 недель, а проверяются на заказах последних 4 недель. Каждому покупателю рекомендуется 10 товаров. Метрики: Precision@10, Recall@10, HitRate@10 и Coverage - доля каталога, попавшая в рекомендации

`дашборд Grafana` - сервис тоже знает историю только до последних 4 недель, а `simulate.py` проигрывает эти недели: запрашивает рекомендации для покупателя и отправляет клик, если покупатель потом действительно заказал рекомендованный товар. На дашборде:

| Панель | Что показывает |
|---|---|
| Запросов в секунду по блокам | нагрузка на каждый блок |
| Время подбора, 95-й процентиль | скорость ответа |
| CTR по блокам | доля показанных товаров, по которым кликнули, — главная бизнес-метрика |
| Доля холодного старта | сколько запросов от новых покупателей, которым досталось только «популярное» |
| Каким методом собраны рекомендации | как часто гибрид переключается на запасные методы |
| Покрытие каталога | какую долю товаров сервис вообще рекомендует |
